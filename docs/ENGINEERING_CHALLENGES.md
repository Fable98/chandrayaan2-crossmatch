# Engineering Challenges & Technical Resolutions

This document records the critical photogrammetric, radiometric, and software engineering challenges encountered and resolved during the development of the Chandrayaan-2 Cross-Sensor Correspondence Engine (SIH PS 26166). Every item reflects real problems documented in git commit history and codebase comments.

---

## Technical Challenges Matrix

| Challenge | Impact | Solution & Verification |
| :--- | :--- | :--- |
| **1. Sun-Azimuth vs. Sensor-LOS-Azimuth Conflation in DEM Relief Compensation** | Planetary relief displacement occurs strictly along the spacecraft's sensor Line-Of-Sight (LOS) look angle, but ISRO/PDS labels only provide solar illumination azimuth (`sun_azimuth_deg`). Early builds inadvertently passed solar azimuth to `ransac_dem_aware_fit()`, shifting crater features in the direction of cast shadows rather than optical perspective nadir, inflating fit RMSE. | Decoupled solar illumination provenance from geometric projection in `ML_model/metadata.py`. In `ML_model/matcher_cfog.py` (commit `c5fb089`), passed `azimuth_deg=None` when spacecraft orbital-track LOS azimuth is unavailable, allowing the relief model to use nadir-relative defaults while recording solar angles strictly as photometric audit metadata. |
| **2. Canonical vs. Dynamic Grid-Size Reporting Inconsistency** | Internal matcher Non-Maximal Suppression (NMS) dynamically scaled grid partitioning (e.g. $4 \times 4$ at 512px, 16 cells) to enforce spatial spread across small crops. Earlier reports quoted dynamic occupancy figures (31%–44% coverage), which gave an inconsistent comparison against fixed-grid evaluations. | Standardized `compute_canonical_metrics()` in `ML_model/metrics.py` to strictly evaluate spatial coverage and entropy over a fixed $10 \times 10$ reporting grid (100 cells), while separately tracking `matching_grid_size`, `adaptive_grid_size`, and `coverage_relative_to_inlier_count` for full auditability. |
| **3. Memory Exhaustion (OOM) on Gigapixel Full-Swath Planetary Rasters** | Evaluating 2D Log-Gabor filter banks (4 orientations $\times$ 3 scales) and Fourier Phase Correlation across full OHRC orbital strips ($12000 \times 40000$ pixels) required tens of gigabytes of RAM, triggering system OOM kills. Reshaping 256-band IIRS hyperspectral cubes into $(H \cdot W, 256)$ for PCA also triggered `MemoryError`. | 1) Engineered `ML_model/tiled_matcher.py` with multi-threaded tiled processing ($1024 \times 1024$ tiles with 15% overlap) orchestrated via `ThreadPoolExecutor` and stitched back into global coordinates.<br>2) Downsampled OHRC to common physical working GSD prior to filter-bank evaluation.<br>3) Added defensive `MemoryError` handling in `ML_model/iirs_multimodal_registrar.py` to prevent silent aborts. |
| **4. PDS3 Header Parsing: Attached Images vs. Detached `.LBL` Files** | NASA LRO NAC products arrive in two distinct formats: detached ASCII `.LBL` labels with external `.IMG` payloads, or monolithic `.IMG` files where PDS3 labels are prepended directly to 16-bit binary pixel arrays without EOF separators. Standard text readers crashed with unicode decode errors or dropped nested projection blocks. | In `ML_model/lro_pds3_parser.py`, implemented dual-mode ingestion: binary inspection of the initial 64 KB header buffer for `.img` files with ASCII error-ignoring decoding, and UTF-8 parsing for `.lbl` files. Implemented recursive dictionary flattening (`_flatten`) to reliably extract GSD, emission, and projection parameters. Verified in `tests/test_lro_pds3_parser.py`. |
| **5. Diametric Shadow Reversal at Extreme Sun-Angle Gaps (`triplet_new_2022`)** | `triplet_new_2022` presents an extreme $162.25^\circ$ solar azimuth disparity (morning vs afternoon illumination). Cratering relief gradients undergo total polarity inversion, causing unconstrained matchers to cluster spurious candidates on isolated rim edges and estimate degenerate projective planes. | Enforced zero-synthetic-fallback architecture: Quality Gate 3 (*Sanity Check Transformation Conditioning*) and Gate 4 (*Spatial Support Check*) detect singular value collapse ($S_{\max}/S_{\min} \ge 20.0$) and spatial concentration ($>60\%$ in single cell), cleanly intercepting the failure with `status="geometric_verification_failed"` rather than fabricating identity transforms. |
| **6. The ~275×–320× Optical-to-Spectrometer Scale Disparity Boundary** | Attempting direct sub-meter tie-point matching between 0.25 m panchromatic OHRC and ~70–80 m IIRS hyperspectral bands spans an unphysical resolution gap where one IIRS pixel averages over $\approx 90,000$ OHRC pixels. Direct matchers hallucinate unphysical mineral boundaries that violate the Nyquist sampling limit. | Implemented the chained homography bridge ($H_{\text{OHRC}\to\text{IIRS}} = H_{\text{TMC}\to\text{IIRS}} \cdot H_{\text{OHRC}\to\text{TMC}}$) in `ML_model/iirs_multimodal_registrar.py`. IIRS is registered honestly as a spatial-spectral overlay, reporting 0 measured inliers on the direct leg and tagging propagated points as `derived_composed_overlay`. |
| **7. Synthetic Proxy Over-Fitting vs. Real NASA CDR Radiometry** | Early tests evaluated LRO NAC reference registration on synthetic OHRC-derived proxies (`warp + blur + noise`), which scored high (37 inliers, 0.27 px RMSE) via optical NCC. On real NASA CDRs (`M1417670274LC`, `M1413636095LC`) with true 16-bit I/F reflectance and ~104°–132° sun gaps, optical NCC found 0 matches. | Retired synthetic proxy numbers from primary benchmarks. Switched to Phase Congruency with Multimodal Mutual Information (`multimodal_pair=True`), successfully registering real CDR footprints at 0.18–0.60 px fit RMSE while transparently grading them as `LOW_CONFIDENCE` due to sparse inliers (5–6 matches). |
| **8. Open-Loop Outlier Vulnerability in Classical RANSAC** | Standard 4-point RANSAC treats all candidate correspondences uniformly, which can be sensitive to heavy outlier ratios when lunar terrain features repetitive crater fields or low-contrast regolith plains. | Integrated `cv2.USAC_MAGSAC` as an opt-in estimator in `ML_model/matcher_cfog.py` (`outlier_method="magsac"`), providing marginalization-based thresholding and covariance-weighted sampling. Verified in `tests/test_matcher_magsac.py`. |
| **9. Chandrayaan-2 PDS Label Ephemeris/Attitude Jitter & Overlap Shift** | PDS label-derived bounding coordinates (`bounds_optical`) in Chandrayaan-2 products occasionally exhibit orbital position and attitude jitter, leading to initial crop offsets where the actual shared ground overlap is partially displaced from nominal metadata extents. | Created `ML_model/overlap_recovery.py` with `recover_overlap_from_content`: performs 1D row/column profile cross-correlation refined by 2D Fourier Phase Correlation to recover true physical offsets and adjust geographic bounding boxes prior to fine feature matching. Verified in `tests/test_overlap_recovery.py`. |
